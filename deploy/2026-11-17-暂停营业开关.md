# 暂停营业开关与 1.0.10 发布

## 当前状态和入口

服务器已部署 `20261117-ordering-1.0.10`，并使用管理员接口明确保存为关闭。电脑后台「KTV 运营」首页顶部的「小程序点餐服务」开关可查看和调整状态。关闭是全体顾客统一状态，已登录、扫码、购物车和旧结算链接均受约束。

顾客端显示「暂停营业」，保留「查看我的订单」、历史订单和工作人员登录入口。管理员仍可维护餐品、查看账单并处理原订单，备货人员继续完成已付订单。切换需二次确认、等待服务端保存成功，失败不显示虚假的成功状态；不同管理员并发操作用独立版本号防止覆盖。

## 服务端

- `ktv_shared_state.ordering` 持久化 `enabled`、`version` 和 `updatedAt`；缺少配置时默认关闭，重启不重置已保存状态。
- `PUT /ktv-api/admin/ordering` 仅限已认证且具有 KTV 管理权限的管理员。顾客、食堂及匿名请求不能修改。
- 顾客 `/state` 关闭时返回空餐品列表及 `orderingEnabled=false`。管理员的原餐品资料不删除。
- 创建订单、模拟支付及微信预支付在共享状态事务内校验开关。关闭后的旧链接、重复下单请求、未付款订单继续支付同样被拒绝。
- 已经向微信发起的支付可能随后完成，其真实支付回调和对账仍正常记录，不丢失已收款事实；商家可继续履约或按正常流程退款。关闭开关不自动取消或退款。
- 修改写入 `store.ordering` 审计记录。原商品、包厢、账号、订单、账单、登录和通知绑定均保留。

## 客户端

小程序与 H5 的首页、购物车、确认订单和支付入口共用暂停页面。待连接或缺少营业状态时不会先展示可下单页面；关闭时清空旧购物车并停用订单列表中的继续支付。开关恢复后重新加载原餐品页面，不需要改代码。

微信客户端版本 1.0.10 已上传成功（1,544,721 字节），用户已确认设为体验版，编译和上传产物均带完整 HTTPS API 地址。旧客户端的静态横幅不能由后端替换，须重新打开新版体验版才能看到暂停页面；服务端停止下单和发起支付已生效。

## 平台操作边界

此次业务暂停不代表微信公众平台已经下架。平台界面访问被站点安全策略阻止，未通过自动化核实或修改平台暂停状态；没有换通道代操作。用户已确认 1.0.10 设为体验版，并说明平台暂停服务暂未操作。如需整款小程序对外不可访问，仍需本人在公众平台办理暂停服务。

恢复营业前须完成所需经营资质、对应服务类目和平台审核。后台开关只控制业务开放，不能替代微信平台的暂停／恢复和审核流程。
