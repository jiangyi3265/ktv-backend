# 三端微信订阅消息（1.0.8）

## 角色和事件

| 角色 | 接收事件 | 小程序入口 |
| --- | --- | --- |
| 顾客 | 备货接单、开始配送、送达、退款成功 | 我的订单、支付结果、订单详情中的「订单进度提醒」 |
| 备货人员 | 已付款待接订单、转派订单 | 我的订单 → 食堂登录 → 接单工作台 |
| KTV 管理员 | 顾客付款下单、备货接单、缺货、超时未接单 | 我的订单 → 商家管理，或扫描电脑后台提供的小程序码 |

管理员使用电脑后台相同的账号密码登录小程序，不需要维护第二套密码。每位管理员应使用独立后台账号；同一个账号只绑定一个微信。账户须有 KTV 管理权限。原 `ktv-admin` 移动账号继续兼容。

电脑后台「接单通知」可显示管理员小程序码、查看各账号绑定及剩余授权次数，分别配置商家/备货模板与顾客订单进度模板。扫码只打开管理入口，不携带登录凭证，也不会自动完成授权。

## 首次连接和后续授权

1. 手机微信打开最新体验版（或已发布版本），进入对应角色页面。
2. 点击「连接微信提醒」，再点击「授权接收微信提醒」，在微信弹窗选择允许。
3. 回电脑后台刷新通知状态。发送记录区分等待绑定、等待授权、发送成功、失败及结果不确定。

当前配置的是一次性订阅模板，每次授权只能发送一条消息。「保持以上选择」并不提供无限次发送权限。要同时收到下单和接单两条，管理员至少需要两次可用授权；顾客的多个进度也分别消耗次数。额度用完后必须回小程序再次授权。电脑网页无法代替微信授权，发送成功不代表已读或手机必定响铃。

商家/备货沿用「订单任务待处理提醒」，顾客使用「订单状态变更提醒」，映射订单编号、状态、更新时间和备注。模板来自本小程序所属类目的微信公共模板库，未混用营销或其他业务模板。

## 后端实现

- 订单支付和状态变更在原业务事务内写入 `ktv_notice_event`。订单回滚不会留下通知，快速连续状态变化也会保留事件。
- 定时任务将事件转入原有 `ktv_notice_outbox`，以订单、角色、事件和版本去重。增加表，不回放历史已完成订单，不修改账单或支付状态。
- 顾客仅能绑定下单微信，通知只发给该订单的顾客；不在管理列表暴露顾客 OpenID。顾客端只发送仍符合当前订单进度的通知，过期阶段取消，避免迟到的「已接单」覆盖已送达状态。
- PC 管理员使用现有后台登录、密码锁定和 JWT 会话，绑定范围为 `admin:pc-用户ID`。退出小程序会撤销该次 JWT。管理员停用或失去权限后，待发送提醒会取消。
- 发送前复核订单状态、接收人、权限、模板和授权次数。任务超过 24 小时取消；网络结果不确定时不自动重复发送，需管理员核对后手动重试。
- 小程序中的管理员入口 scene 不参与包厢解析，防止扫管理码出现包厢无效提示。

## 回归结果

- 后端 80 项测试通过，包括事务回滚、快速状态流转、两位 PC 管理员隔离、撤权后取消、顾客微信归属与退款通知。
- 客户端 34 项测试通过，包括 PC Bearer/原食堂 token 分流、上传认证、会话切换和管理员 scene。
- 浏览器验证三端入口、电脑模板配置、320/390/430 宽度；另外 4 项登录退出隔离回归通过。
- 微信开发者工具验证三角色连接及授权、拒绝授权不增加额度、旧账号绑定响应不会污染新账号。以上通知发送及授权均使用模拟接口，不发送真实消息。
- 构建产物扫描覆盖三个源码仓库、后端 JAR、694 个 Web 文件和 508 个小程序文件，未发现已知生产凭据或明确 Token/私钥特征。

真实微信接收仍需每位使用者亲自允许订阅，并以正常业务订单验证实际送达；模拟测试不能证明手机真实收信、响铃或用户已读。

## 复测方式

后端在仓库根目录运行 `mvn -pl ruoyi-admin -am test`。前端在 ktv-app 运行 `npm test`。

`npm run test:notifications-browser` 需要 Playwright、已启动的 H5 与电脑后台，默认端口分别为 5189 和 5190；通过 `PLAYWRIGHT_MODULE`、`KTV_TEST_APP_ORIGIN`、`KTV_PC_URL` 覆盖。所有业务请求均为测试桩。

`npm run test:notifications-native` 需要微信开发者工具打开当前微信编译产物并启用自动化，默认 WebSocket 为 `ws://127.0.0.1:9441`；通过 `MINIPROGRAM_AUTOMATOR_MODULE`、`KTV_AUTOMATOR_WS` 覆盖。仅在隔离的开发工具项目运行，会清除测试项目的三角色本地会话，不在真实用户手机操作。测试报告默认保存在忽略目录 `.local`，不提交凭据或生产业务数据。
